# seamless-fs (`sfs`) の仕様

カレントディレクトリのファイルを HTTP で配り、リレー(`seamless-fs-relay`、Cloudflare Worker)を通して、他の `sfs` サーバーのファイルも一覧に出す。他サーバーのファイルのリンクは、そのサーバーを指す(中継はしない)。

## 設定(環境変数。カレントの `.env` が優先)

| 名前 | 意味 |
|---|---|
| `HOST` / `PORT` | 待ち受けるアドレス |
| `WORKERS` | ワーカー数(1以上) |
| `ORIGIN` | 他のサーバーからこのサーバーに届くアドレス(http / https)。末尾の `/` は付けても付けなくてもよい |
| `RELAY_URL` | リレーのアドレス(http / https。https を推奨。http が localhost 以外だと警告) |
| `TOKEN` | リレーとの共通トークン。空は起動しない。16文字未満は警告 |

設定に誤りがあると、起動時にそれを書いて終了する。

## 動作

1. 起動時: リレーに「このサーバーは消えた」を送ってから(前回の残りを消す)、ファイル一覧を `PUT <RELAY_URL>?first=true` で送る。`first` は、リレーが他サーバーのファイルを返すための印。
2. 実行中: カレントディレクトリ以下の変化を見て、変化があれば10秒おきに一覧を送り直す(隠しファイルだけの変化は無視)。
3. 停止(Ctrl-C、Unix では SIGTERM も): リレーに `DELETE` を送ってから止まる。
4. リレーからの `PUT /` で、他サーバーの一覧(`{origin, files}`)を受け取って入れ替える。`DELETE /` で消す。どちらも `Authorization` ヘッダーが `TOKEN` と完全に一致したときだけ(一致しなければ 401)。

通信の形式(JSON)は変えていない。ファイル1件: `{origin?, parent, url?, name, size}`。`parent` は `/a/b/` の形。

## 配るもの・出すもの

- ファイルとディレクトリ一覧。`.` で始まる名前(と、その下)は、配らず、一覧にも出さず、リレーにも教えない。
- ルートの外を指すシンボリックリンクは、配らず、一覧にも出さない。
- 一覧のページは `Content-Security-Policy` でスクリプトを許さない。全レスポンスに `X-Content-Type-Options: nosniff`。

## 他サーバーから受け取るもの(信用しない)

- `origin` と `url` は http / https の URL だけ。ほかの形式(`javascript:` など)のファイルは捨てる。
- 名前に `/` や制御文字、ディレクトリに `..` や `\` があるファイルは捨てる。
- 受け取る数に上限: リクエスト本体 500 KB、1サーバーあたり 20,000 ファイル、256 サーバー(超えると 413)。
- 同じ名前のフォルダが複数のサーバーにあるときは、`origin` の文字順で最初のサーバーを指す(順序が毎回変わらない)。このサーバーに同名のフォルダがあれば、そちらを出す。

## 構成(`src/`)

`main`(起動)、`config`(設定)、`confine`(配る範囲の制限)、`auth`(トークン)、`model`(やりとりする形と検査)、`registry`(他サーバーのファイル。ディレクトリごとの索引)、`api`(リレーからの呼び出し)、`listing`(一覧ページ)、`scan` / `sync` / `relay`(リレーへの通知)。

## ビルド

`cargo build --release`(実行ファイル名 `sfs`)、`cargo test`。

## セキュリティ上の注意

- `TOKEN` はリレーと全サーバーで共通。漏れたら全部の `.env` とリレーを変える。
- 配るのはカレントディレクトリ全体。秘密のファイルは置かないか、`.` で始まる名前にする。
- リレーは登録された `origin` へ PUT する。信用できないサーバーを登録しない。
